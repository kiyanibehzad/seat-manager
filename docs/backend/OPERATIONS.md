# قرارداد اعلان، ایمیل و کارهای دوره‌ای

اعلان فقط به recipient_id خودش تعلق دارد؛ خواندن/علامت‌گذاری مالکیت را سمت سرور بررسی می‌کند. Events::notify باید داخل همان transaction عملیات اصلی فراخوانی شود تا دادهٔ اصلی، notification و mail_outbox با هم commit/rollback شوند. event_key پایدار برای هر رخداد و گیرنده، تولید تکراری را متوقف می‌کند. body و action_url هر گیرنده فقط اطلاعات همان فرد را داشته باشند؛ اطلاعات دو طرف انتقال برای بخش شخصی ترکیب نشوند.

رویدادهای هویت مرحلهٔ اول حفظ شده‌اند. مرحلهٔ دوم request.created را برای admin/operator، request.review/result را برای صاحب درخواست، seat.changed را برای صاحب همان حساب و premium.expiring/expiry.action_required را از تخصیص واقعی تولید می‌کند. ایجاد مدیریتی/لیستی هم رمز اولیه را فقط به outbox واقعی می‌فرستد. هیچ رویدادی برای پرکردن ظاهری اعلان ساخته نمی‌شود.

mail_outbox: payload با AES-256-GCM و app_key خارج وب رمزگذاری می‌شود؛ توکن‌ها در auth_tokens فقط SHA-256 هستند. statusها pending → sending → sent و برای شکست قطعی پیش از DATA، retry با فاصلهٔ ۶۰/۱۲۰ ثانیه تا ۳ تلاش پیش‌فرض (سقف تنظیمی ۵) است. Message-ID پایدار و idempotency_key یکتا دارند. workerها قفل DB مشترک می‌گیرند؛ هر پیام در transaction claim می‌شود. بعد از sent متن رمزگذاری‌شده پاک می‌شود. ایمیلِ token مصرف‌شده/منقضی پیش از ارسال لغو می‌شود. تغییر رمز/غیرفعال‌سازی ایمیل‌های قدیمی auth و رمز اولیه را که هنوز ارسال نشده‌اند لغو می‌کند.

SMTP تضمین exactly-once ندارد: اگر قطع اتصال حین DATA یا بعد از پذیرش و پیش از ثبت sent رخ دهد، ارسال می‌تواند انجام شده باشد. چنین پیام‌هایی uncertain می‌شوند و **خودکار retry ندارند**. sending باقی‌مانده از worker قطع‌شده پس از ۱۵ دقیقه نیز uncertain می‌شود. مسئول در مرحلهٔ عملیاتی باید با لاگ سرور SMTP وضعیت را بررسی کند؛ ابزار ارسال دوبارهٔ خودکار یا دکمهٔ retry عمومی ساخته نشده است. خطای ذخیره‌شده فقط کد ثابت است، نه ErrorInfo یا متن پیام. payload حالت‌های terminal ناموفق پس از ۷ روز در cron پاک می‌شود. تاریخچهٔ خود ردیف/اعلان حذف نمی‌شود.

در محیط توسعه مقصد شبکهٔ worker فقط 127.0.0.1:10279 است. sink هیچ relay ندارد و خود mailbox را رمزگذاری می‌کند؛ محتوای پیام/رمز/توکن را چاپ نمی‌کند. کلید و فایل‌های mailbox از خروجی بسته کنار گذاشته می‌شوند.

## یادآوری Premium موقت — dispatcher مرحلهٔ دوم فعال است

Domain::apply در همان transaction وضعیت واقعی، یادآوری assignment/version جاری را تنظیم می‌کند. تمدید همان assignment_id را با version تازه و return_seat اصلی حفظ می‌کند؛ تغییر نوع/پس‌گرفتن/انتقال، assignment قبلی را می‌بندد و یادآوری ارسال‌نشدهٔ آن را لغو می‌کند. موعد یک روز تقویمی ایران پیش از ends_at است و UTC ذخیره می‌شود.

bin/cron.php ابتدا Reminders::dispatch را اجرا می‌کند. dispatcher زیر همان قفل عملیات، assignment واقعی، current بودن، owner، نوع Premium، version و end را دوباره کنترل می‌کند. رکورد stale/بسته/مصرف‌شده یا پایان‌گذشته یادآوری خصوصی تازه نمی‌سازد. برای نسخهٔ معتبر، notification و outbox با لینک renew_account همان حساب و dispatched_at در یک transaction ثبت می‌شوند. تکرار cron برای همان نسخه پیام تازه نمی‌سازد. متن انتقال/یادآوری شخصی فقط ایمیل همان گیرنده را دارد؛ مشخصات طرف دیگر منتقل نمی‌شود.

پایان دوره و سیت مالک غیرفعال، action alert جدا برای admin/operator می‌سازند. assignment_alert_markers تکرار alert را برای همان نسخه/وضعیت هویت می‌بندد. این alertها هیچ سیت، خرید یا ظرفیتی را آزاد/کم نمی‌کنند؛ dashboard نیز از واقعیت DB مشتق می‌شود. بعد از پایان، پیام «یک روز باقی است» ارسال نمی‌شود.

## زمان‌بندی محلی

dev-services.py بعد از اتصال DB و اجرای migrationهای معتبر، فرآیند خصوصی local-cron را بالا می‌آورد. این فرآیند هر دقیقه bin/cron.php را با **config پیش‌فرض dev** اجرا می‌کند، نه config تست. سیستم launchd/crontab تغییر نمی‌کند. ready بودن runner از pid و اولین cron-status معتبر کنترل می‌شود؛ status/stop همان ابزار آن را هم پوشش می‌دهند. status آخر در storage/run/cron-status.json فقط شمارنده، pid و زمان UTC دارد و هیچ متن ایمیل یا secret را منتقل نمی‌کند.

SMTP در development/test در worker به 127.0.0.1:10279 محدود است. sink relay ندارد و mailbox رمزگذاری می‌شود. برای QA پورت 8788 cron خودکار فعال نیست؛ مرورگر می‌تواند فیکسچر را بدون تغییر پس‌زمینه بررسی کند. اجرای عمدی cron تست باید با config تست انجام شود؛ هیچ SMTP خارجی مجاز نیست.

## ثبت واقعیت، ظرفیت و هم‌زمانی

تمام mutationهای حساب/درخواست/سیت ابتدا identity_guard و سپس operations_guard را با ترتیب ثابت قفل می‌کنند. actor، نسخهٔ auth و مجوز دوباره خوانده می‌شوند. command key یکتای actor، payload hash و پاسخ، همراه همان transaction ثبت می‌شوند. هیچ ارسال SMTP یا اقدام OpenAI داخل تراکنش وجود ندارد. تداخل موقت InnoDB حداکثر دو بار بازاجرا می‌شود.

ظرفیت با یک statement snapshot خوانده می‌شود: purchased−actual assigned−unassigned holds. GETهای ترکیبی queue/dashboard/history از یک snapshot تراکنشی مشترک استفاده می‌کنند. بعد از هر نتیجهٔ جزئی hold هر نوع = max(0, مجموع هدف همان نوع در operation − مجموع واقعی همان نوع در حساب‌های قفل‌شدهٔ همان operation) است. بنابراین آزادشدن Premium مبدأ پیش از تکمیل، برای مقصد همان عملیات نگه داشته می‌شود؛ ظرفیت مضاعف ساخته نمی‌شود. ترتیب معکوس ثبت واقعیت می‌تواند کسری واقعیِ موقت ایجاد کند؛ این کسری آشکار و مانع تخصیص تازه است، نه دلیل ساختن تغییر فرضی طرف دیگر.

complete به تأیید تازهٔ همهٔ حساب‌ها با email/owner/version و تطبیق هدف نیاز دارد. abort پس از برگشت واقعی تمام طرف‌ها با outcome=rolled_back و status=cancelled خاتمه می‌یابد؛ goal موفق اعلام نمی‌شود. سابقهٔ قبل/بعد/عامل/ثبت/مشاهده/دلیل append-only است و API حذف/ویرایش تاریخچه ندارد. اصلاح مستقلِ حساب قفل‌شده قبول نیست؛ نتیجهٔ جزئی/اصلاح همان operation باید ثبت شود.

تبدیل پولی و کاهش تعداد خرید فقط به تأیید admin و واقعیت ثبت‌شده وابسته‌اند. شروع/زمان‌بندی خرید را عوض نمی‌کند. اگر downgrade از Standard آزاد استفاده کند، خرید ثابت است؛ اگر واقعاً تعدادها تبدیل شده باشند، delta Standard+1/Premium−1 هم‌زمان با حساب ثبت می‌شود. rollback ظرفیت هم خودکار نیست؛ تأیید مستقلِ برگشت واقعی تعدادها لازم است.

## قواعد اجرا و حفظ داده

migration 001 ثابت مانده است؛ 002 فقط جدول/setting جدید اضافه می‌کند. پیش از اعمال روی dev، backup خصوصی تهیه و hash تمام کاربران قبل/بعد مقایسه شد. استقرار عمومی، SMTP واقعی و اتصال خودکار OpenAI در این مرحله انجام نشده‌اند. پایگاه dev و حساب انسانی حفظ شده‌اند. تست‌های run.php و operations.php فقط acc_manager_test را reset می‌کنند و فیکسچر مرورگر را جایگزین خواهند کرد؛ هنگام QA اجرا نشوند.
